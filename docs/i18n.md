# i18n/l10n — Guia rápido

- Biblioteca: i18next + react-i18next + i18next-browser-languagedetector.
- Pastas:
  - `web/src/i18n/index.js` — setup (fallback en, detector localStorage → navigator → query).
  - `web/src/i18n/locales/{en,pt,es}/common.json` — dicionários.
- Convenções de chave: `nav.dashboard`, `auth.login`, `store.tabs.items`, `wp.contentMd`.
- Pluralização: usar `t('itens', { count })` e chaves com `one`/`other` quando necessário.
- Placeholders: `t('store.title', { id })` → `Loja #{{id}}`.
- Acessibilidade: troca dinâmica do `<html lang>` já integrada no setup.

## Processo de tradução
- Adicione chaves em EN primeiro.
- Rode `npm run i18n:extract` para gerar `missing.json` em cada idioma.
- Traduza e mova chaves de `missing.json` para `common.json` do idioma alvo.
- PRs não devem introduzir strings cruas em páginas; use `t('…')`.

## API
- Locale negotiation: `user.locale` → `Accept-Language` → `DEFAULT_LOCALE`.
- Preferências do usuário: `GET/PUT /api/v1/me/preferences` com `{ locale: 'pt_BR'|'en_US'|'es_ES' }`.
- Templates: `render_template(name, locale, ctx)` resolve `name.{pt|es|en}.md.j2` com fallback para EN e para o arquivo base.
- Formatação: `babel` disponível via `format_currency`, `format_datetime`, `format_decimal`.

## Env
- `.env.example`: `DEFAULT_LOCALE` (padrão `en_US`) e `SUPPORTED_LOCALES` (padrão `en_US,pt_BR,es_ES`).
